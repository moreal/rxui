# ADR-0009: Treat the M5 graph runner as a pre-benchmark smoke harness

- Status: Accepted
- Date: 2026-08-19

## Context

M5 asks for a small-graph benchmark harness after correctness exists. The full
architecture benchmark report additionally requires generated bytes before and
after minification, build/elaboration, mount, update, DOM-write, graph/cache
memory, browser versions, and environment disclosure. Those measurements require
the broader M10 performance suite and representative large applications. Calling
the first 1,000-step native loop a complete benchmark would overstate its scope.

## Decision

The M5 `leanrx_graph_bench` runner is a correctness and instrumentation smoke
harness, not a published performance benchmark. It runs setup and a differential
sanity check before timing, then reports update-loop elapsed nanoseconds and exact
derived/sink work counts. CI asserts only the deterministic scenario and counts;
it sets no timing threshold.

M10 must extend or replace this runner with the complete architecture report,
including generated sizes, separate build/mount/update measurements, DOM writes,
memory, browser/tool versions, warm/cold methodology, and environment details,
before LeanRx publishes comparative performance claims.

## Consequences

M5 establishes a reproducible command and catches gross work-count regressions,
but it makes no speed or memory claim. The local elapsed value is recorded as an
observation, not a baseline threshold. This explicitly preserves every final
benchmark requirement for M10.

## Validation

`./scripts/check_bench.sh` first relies on the native reference/optimized
correctness check and then requires 1,000 alternating diamond updates to report
exactly 3,000 derived and 1,000 sink evaluations. The command runs identically in
local and CI gates.
